# Keel evaluation (v0)

Does a Keel document set help an agent build a small greenfield project, and what does it cost? This folder measures that, repeatably, so later changes to Keel's output (for example shorter execution documents) can be compared with a fixed baseline.

## Method

**Tasks** (`tasks/<id>/`). Each is a small greenfield build with a precise spec:

| Task | What the agent builds |
|---|---|
| `ledger` | A shared-expense command-line tool (integer cents, remainder rule, greedy settle) |
| `shortlinks` | A URL-shortener HTTP service (validation, rolling-window rate limit) |
| `booking` | A meeting-room booking library (strict time parsing, half-open overlap rules) |

Each task folder holds:

- `prompt.md`: what the agent is asked. **The same prompt is used in every condition.**
- `AGENTS.min.md` + `CLAUDE.min.md`: the minimal-docs condition (CLAUDE.md is one line, `@AGENTS.md`, so Claude Code loads it).
- `founder-answers.md`: the interview answers used once to generate the Keel set.
- `keel/`: the Keel document set, generated by Keel 2.5.6 from `prompt.md` + `founder-answers.md` (`run.mjs --gen-keel <id>`). Committed, so every run uses the same documents.
- `tests/`: hidden acceptance tests. The agent never sees them.
- `rubric.md`: what the judge checks. Items marked MUST decide its verdict.
- `reference/` and `broken/`: a solution that must pass both graders, and a deliberately broken one that must fail both.

**Conditions.** Every task runs in three:

| Condition | The work folder starts with |
|---|---|
| `none` | nothing (an empty git repository) |
| `min` | a 6-line AGENTS.md (and the one-line CLAUDE.md) |
| `keel` | the full Keel 2.5.6 document set (prototype tier) for the task |

**The agent.** `claude -p` (Claude Code, headless) with `--setting-sources project --strict-mcp-config`, so no user settings, hooks, plugins or MCP servers leak in, and the work folder sits outside this repository, so no parent CLAUDE.md does either. Project settings stay on, so a Keel-generated `.claude/` behaves as it would for a user. Default model: `sonnet`. The SDK and `claude -p` are measuring tools here only.

**Grading** (`grade.mjs`). A run succeeds only when both pass:

1. The hidden tests: all of them, run with `node --test` against the agent's folder.
2. The judge: a different model from the agent (default `opus`), with no tools, reads the spec, the rubric and the agent's source (not its docs) and marks each rubric item pass or fail with a reason. The verdict is computed by `grade.mjs` from the MUST items, never taken from the model.

**Recorded per run:** success, tests passed, judge verdict and failed items, cost (USD at list price, as Claude Code reports it), output tokens, cache reads and writes, turns, wall time, tool calls by name, and which doc files the agent opened.

## Commands

```bash
node evals/grade.mjs --selftest                 # prove both graders: reference passes, broken fails (about $0.40)
node evals/run.mjs --gen-keel ledger            # one-off: regenerate a task's Keel fixture
node evals/run.mjs --tasks ledger,shortlinks,booking --conds none,min,keel --reps 3 --cap-usd 40
node evals/grade.mjs ledger <folder>            # grade any folder by hand
node evals/run.mjs --out <dir> --rescore        # recompute usage + doc reads from saved transcripts (no model calls)
```

`run.mjs` stops before a run when the spend cap would be crossed, gives each run its own `--max-budget-usd`, and resumes a stopped batch when given the same `--out`. Raw transcripts, the agent's files and `summary.json` / `summary.md` go to `results/raw/<stamp>/`, which git ignores. Findings go in `results/`.

## What a result may and may not recommend

The suite measures what an agent needs at build time. It may justify shortening **execution-tier** documents (AGENTS.md, CLAUDE.md, COMMANDS, IMPLEMENTATION_PLAN, RUNBOOK, DEPLOYMENT, PRODUCT, indexes). It never justifies shortening a **record-tier** document or dropping a document type: those carry the reasons a later reader needs, which a small build task does not test.

**Long runs.** `run.mjs` prints a `[heartbeat]` line every 60 s while a child `claude -p` run is silent; run it in the background and watch its output so the watching agent is never idle. Set `EVAL_RAW` to a folder outside the worktree: `results/raw/` is git-ignored and is lost when a temp's worktree is torn down. `--gen-keel` also writes `tasks/<id>/keel-gen-usage.json` (committed) so the generation's tokens and cost are kept with the fixture.
