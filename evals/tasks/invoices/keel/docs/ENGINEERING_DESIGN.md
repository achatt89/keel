# invoices — Engineering Design

**Status:** Draft · Reads: [BRD.md](./BRD.md) · Feeds: [ARCHITECTURE.md](./ARCHITECTURE.md), [LLD.md](./LLD.md), [NFR.md](./NFR.md)

## 1. Design pillars

| # | Pillar | Meaning |
|---|---|---|
| 1 | Correct to the cent | Integer arithmetic only; one rounding rule; proven by tests |
| 2 | Legal-document integrity | Issued invoices are never edited or deleted; numbers are gapless and never reused |
| 3 | Fail closed | Validate everything first; a failed call changes nothing |
| 4 | Boring and small | Stdlib only, one module, no clever abstractions |

## 2. Domain model

| Entity | Fields | Notes |
|---|---|---|
| Customer | `id` (`C0001`…), `name`, `country` (ISO 3166-1 alpha-2) | id generated by the ledger |
| Invoice | `number`, `customerId`, `lines[]`, `issuedAt` (UTC ISO string), `vatRatePercent`, `net`, `vat`, `gross` (integer cents), `status` (`issued`\|`void`) | rate and amounts are computed once at issue and stored (A-06) |
| Line | `description` (optional `[ASSUMPTION]`), `quantity`, `unitPrice` (integer cents) | quantity type: OD-03 |

## 3. Data classification

| Tier | Data | Handling |
|---|---|---|
| C0 | VAT table, error codes | public, in code |
| C1 | Customer business names, amounts, invoice numbers | business-confidential; no personal data beyond business names (founder answer); never written to logs beyond the console summary |

## 4. Non-negotiables

| # | Rule | Why | Decision |
|---|---|---|---|
| N-01 | Money is integer cents; no floating-point arithmetic or `toFixed`/`toLocaleString` on money | float error breaks "correct to the cent" | [ADR-001](./adr/ADR-001-money-integer-cents.md) |
| N-02 | VAT = one half-up rounding of `net × rate` at invoice level, in one function | founder rule; line-level rounding drifts | [ADR-002](./adr/ADR-002-vat-rounding-and-rates.md) |
| N-03 | Only the ledger allocates ids and numbers, only after validation succeeds, never reusing one | gapless numbering; never trust caller ids | [ADR-003](./adr/ADR-003-gapless-numbering-per-year.md), [ADR-006](./adr/ADR-006-ledger-isolation-no-caller-ids.md) |
| N-04 | No API edits or deletes an issued invoice; void only flips `status` | legal document | ADR-003 |
| N-05 | Every public function validates all input before changing state; failure leaves the ledger unchanged | atomicity | [ADR-005](./adr/ADR-005-error-model.md) |
| N-06 | Callers never get references to internal state (return frozen copies) | prevents mutation behind the ledger's back | ADR-006 |
| N-07 | Stored times are UTC; the Berlin date comes from one helper using `Intl` | one time-zone rule | [ADR-004](./adr/ADR-004-dates-utc-and-berlin.md) |
| N-08 | Failures throw `InvoiceError` with a code from the closed set | stable contract for scripts | ADR-005 |
| N-09 | Standard library only; no dependencies of any kind | supply chain, longevity | [ADR-007](./adr/ADR-007-stack-node20-stdlib-esm.md) |
| N-10 | CSV output is byte-exact and locale-independent | accountant imports without edits | [ADR-008](./adr/ADR-008-csv-export-format.md) |
| N-11 | Internal maps keyed by user strings use `Map`, never plain objects | prototype-pollution class of bugs | ADR-006 |

## 5. Module decomposition

One source file `src/invoices.js` (exports `createLedger`, `InvoiceError`) until size demands a split (Phase 3 adds storage; split decision then, as an ADR). Internal sections: validation · money/VAT · dates · numbering · ledger · CSV. Detail: [LLD.md](./LLD.md).

## 6. Build order

Phase 1 core (scaffold + proof of every rule) → Phase 2 export (needs Berlin dates, numbering order) → Phase 3 storage (needs a stable domain model). See [IMPLEMENTATION_PLAN.md](./IMPLEMENTATION_PLAN.md).
