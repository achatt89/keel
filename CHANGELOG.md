# Changelog

All notable changes to Keel are documented here. Format loosely follows
[Keep a Changelog](https://keepachangelog.com/); versions follow [SemVer](https://semver.org/).

## [2.6.4] — 2026-11-16
<!-- headline: Business requirements say only what was decided. -->

The business requirements document (BRD) now says where each assumption comes from. In our 2.6.3
test, every remaining contradiction between the documents and the code came from the generated
BRD stating code details nobody had decided, such as that names are stored trimmed, or that two
features share one helper. Now each BRD assumption names its source: your answer in the
interview, the decision record that settles it, or *unvalidated*. A code detail with no answer
behind it goes in a decision record or the low-level design instead. Doc sync compares these
statements with the code and records any difference next to the original text, which is never
rewritten or removed. The merge step also updates every status line in one commit, then runs the
drift check.

**What we checked.** The new checks run on the saved folders from our earlier test runs, with no
model calls: the 2.6.3 session that left a status line on its branch after the merge is reported,
and no other saved session gets a false report. The effect on drift in new sessions is not
measured yet.

### Added
- **A Source column in the BRD Assumptions table** (new projects), and guidance that risk
  mitigations naming code structure cite their decision record.
- **`/keel check` reports two more kinds of drift:** `status-lag`, a status line in `AGENTS.md` or
  `CLAUDE.md` still saying a phase is on its branch after the plan shows it merged; and
  `brd-unsourced`, an assumption with no source, in a BRD whose table has a Source column.

### Changed
- **Doc sync** compares BRD assumptions, risk mitigations and product acceptance notes that name
  code behaviour with the code. When the build differs it records it, in order of preference, as
  the decision record's build deviation, as "superseded by the build" after the original text, or
  as an open decision for you when you were the one who said it. No row is removed.
- **The merge step** of phase and change scripts makes all its status edits in one commit and
  runs `node .keel/check.mjs` afterwards.

### Upgrading
- `/keel upgrade` offers the Source column for an existing BRD, with sources proposed from the
  interview transcript and *unvalidated* where none applies. It is applied only with your
  approval; the assumption text is not changed.

## [2.6.3] — 2026-11-16
<!-- headline: README examples are tested, not just written. -->

README examples and error tables now sit under test. In our 2.6.2 test, the documents Keel keeps
stayed in step with the code, but the project's own README still went wrong in small ways: an
error code described for the wrong case, and an off-by-one number in a worked example. Now each
README code example is a file in `examples/` that a test runs and compares with its stated output,
and each documented error code has a test that triggers it. A wrong example fails the tests
instead of waiting for someone to notice. This adds no model work to a session.

**What we measured (n=1, a signal only).** One three-session run of our inventory test task,
with one tested model, on documents generated by 2.6.3. The README stayed under test throughout
(5 examples and the error table, all passing), and no session had a README contradiction, against
2 of 6 sessions on 2.6.2. Every session still had some document that contradicted the code: a
detail the generated business requirements stated beyond the founder's answers (for example, that
names are stored trimmed). That gap is not covered by this release. One run is too few to claim a
rate.

### Added
- **Docs under test.** A new convention, a standing rule in the implementation plan, and a README
  section in the phase and change task briefs. A phase that delivers a README gets the exit gate
  "README examples and error table pass".
- **`/keel check` reports untested README content** (`docs-untested`): a runnable code block or an
  error table with no `keel:example` / `keel:asserts` marker, or a marker naming a file that does
  not exist (projects on 2.6.3, or with a marker).

### Changed
- **Doc sync** treats an untested README example or error table as a gap: it adds the example or
  test and the marker. It never fixes the README text alone.

### Upgrading
- `/keel upgrade` offers the examples runner, the markers and the standing rule for an existing
  README. It is applied only with your approval.

## [2.6.2] — 2026-11-16
<!-- headline: Decision records and design docs keep up with the code. -->

Doc sync now brings decision records and design documents up to date with what was built, not only
the plan and changelog. In our multi-session test, the plan and changelog stayed right, but older
decision records kept saying a feature was "not built" after later sessions built it, and the
architecture and low-level design described data shapes the code did not use. Doc sync now
rewrites each affected decision record's status and build-deviation row, compares the design
documents with the code, and runs the drift check before it hands back.

**What we measured, and what is not covered.** On one three-session test task (our v1 inventory
task, one tested model, 6 sessions), stale decision records and architecture or low-level design
contradictions dropped to 0 of 6 sessions, against 6 of 9 sessions with some contradiction on
2.5.6. That is a small sample and an indication, not proof. The release did **not** meet the pass
rule we set (contradictions in at most 1 of 9 sessions): 2 of 6 sessions still had a wrong
statement in the project's own README, an error-code meaning and the numbers in a worked example.
README accuracy is not covered by this release; making README examples runnable checks is
planned for 2.6.3.

### Changed
- **Doc sync reconciles decision records.** Every record the work touched, or whose phase it
  advanced, gets its Status cell moved to Built and its Build deviation row filled with what was
  actually built. Wording an earlier sync left, like "Phase 2–3 methods not built", is checked
  again on every sync. The decision text itself is never changed.
- **Doc sync compares the design documents with the code.** Data shapes and store fields, exported
  names, module sections, error codes and file layout in ARCHITECTURE, LLD and the README are
  checked against the code the work touched, and fixed to match. A change that breaks a recorded
  decision becomes a Build deviation row or a new decision record.
- **Completing a phase that a decision record names is never a status-only sync,** so it always
  goes to the doc-sync role.

### Added
- **`/keel check` reports stale decision records** (`adr-status-stale`): a Status cell, Build
  deviation row or index row that says "not built" for phases the plan shows done, or a record
  still Accepted after its phase is done. Doc sync runs the check as its last step.

### Upgrading
- `/keel upgrade` offers to replace `doc-sync.js` and the doc-sync subagent (they hold no project
  content) and lists any stale records; the next doc sync fixes them.

## [2.6.1] — 2026-11-16
<!-- headline: Every document type in every project. -->

Keel now writes every document type for every project. Until now a small project did not get the
documents that did not fit it yet, such as a high-level design for a one-module tool or a
deployment guide for something that runs only on a laptop, and which ones were left out could
change from one run to the next. Now each such type is a short stub at its usual path. It says
why the type does not apply yet, quoting your interview answer, what would make it apply, and where
those facts live meanwhile. Documents that do apply are written in full, as before.

### Added
- **Stubs for document types that do not apply yet.** A new stub template; the catalog lists every
  type with its stub trigger. During the interview Keel shows every type as full or stub, with the
  reason, and you can change any of them. AGENTS.md lists the stubs in one document-map row.
- **`/keel check` finds three more kinds of drift.** `missing-type`: a document type with neither a
  file nor a stub (projects on 2.6.1 or with a stub). `stub-triggered`: a stub whose reason no
  longer holds, for example a Dockerfile next to a DEPLOYMENT stub, a package manifest next to a
  COMMANDS stub, front-end files next to a DESIGN stub. `rules-missing`: a decision record whose
  header names code paths that no area rule cites.

### Changed
- **Generation reads the document catalog in full** before proposing the set, instead of choosing
  from memory.
- **`/keel upgrade`** offers a stub for each document type an existing project is missing, with the
  reason taken from its existing docs, or the full document where the reason no longer holds.
  Nothing is applied without your approval, and existing documents are not changed.

## [2.6.0] — 2026-11-16
<!-- headline: Leaner instructions, the same full set of documents. -->

Keel still writes every document it wrote before. What changes is the part an agent reads on
every run: a new project now loads about 8.7 KB at session start instead of 16.1 KB, and the Keel
skill itself is read in pieces instead of 100 KB at a time. Nothing was cut from a record
document, and no document type was removed.

Why only the working documents: *execution* documents (AGENTS.md, CLAUDE.md, COMMANDS, the
implementation plan, runbook, deployment, the indexes, hooks and subagent files) are loaded and
acted on in every session, so each extra line costs on every run. *Record* documents (BRD, PRD,
engineering design, architecture, HLD, LLD, decision records, NFR, design, compliance, threat
model and the rest) are opened for one question, and their value is being complete; they stay
full and are only checked for drift. Every line that left an execution file now lives in the one
document or script that already held it, word for word.

These changes were measured first. The evaluation in `evals/` ran the same tasks with no
documents, a minimal AGENTS.md and the full Keel set, then again with 2.6.0
(`evals/results/v0-baseline.md`, `evals/results/regression-2.6.0.md`). With the 2.6.0
documents, agents still finished every task (9 of 9 runs, as before), at about 14% lower
cost per run.

### Changed
- **A leaner keystone.** AGENTS.md workflow steps are one line each; the rules live in the
  implementation plan's "Standing rules", the mechanics and delegation in
  `.claude/workflows/README.md`. CLAUDE.md points to DESIGN.md §12 for the UI command map and
  names the review roles in one line. A written placement rule gives each kind of instruction one
  home.
- **Doc sync is proportional.** Work that changes only status lines is synced in one pass by the
  agent that did it. Work that changes a decision, requirement, command or other record document
  still goes to the doc-sync role, with review and at most three rounds.
- **Plain subagent descriptions.** The design, security and doc-sync subagents state when to use
  them, without "MUST BE USED PROACTIVELY".
- **Verify runs a real check, and a check counts only once it has been seen to fail.** Every met
  gate above `code-read` records how its check failed on broken code (`failSeen`), or it is
  `partial`. `node .keel/doc-size.mjs --evidence` rejects a Verify record that claims `prod-live`,
  has an unproven met gate or lists no gates.
- **A slimmer Keel skill.** SKILL.md is a short router (11.5 KB, from 100 KB) and each mode loads
  its own file from `references/modes/`, moved word for word. `/keel change` reads about 14 KB
  instead of 100 KB. The skill description is under 1,024 characters, with its trigger phrases
  first, so every mode is visible in the skill listing.

### Added
- **Stops and an end-of-run report.** AGENTS.md has one "stop and ask" line, filled from the
  project's own decision, NFR, compliance and threat-model rows, and asks every run to end with
  four lines: blocked on me, changed, found, could not confirm.
- **Area rules that load by path.** `.claude/rules/<area>.md` files with `paths:` frontmatter
  load only when matching code is touched. Each line is a rule plus the decision or NFR ID that
  holds the reason, never a copy of it.
- **A short header on new decision records:** `id`, `status`, `paths` and `check`. Who approved a
  decision stays in the record's own table, so it is not written twice. Decision records written
  before 2.6 are never rewritten and never given a header.
- **`/keel check`, a read-only drift check.** `.keel/check.mjs` compares the documents with the
  repository with no model call: missing keel files, dead links and anchors, the decision index
  against the decision files, header and rules-file mismatches, finished phases with open gates or
  missing evidence, and dependencies no design document names. Claude reads the cited lines only
  when there are findings. Nothing is written; it exits 1 on findings, so it can run in CI.
- **A gates hook.** The `keel-gates` Stop hook runs the size and link check when Claude stops and
  blocks once on a broken split link. It cannot loop. The modern-web-guidance reminder now fires
  on UI files only, once per session.
- **Team answers (opt-in).** A project owner can hand interview rounds to teammates as packet
  files in git: `/keel answer <packet>` answers one round, `/keel merge` lists gaps and
  contradictions for the named decider. Every answer is marked human or Claude, and a Claude
  answer never settles a dispute. The single-person interview is unchanged and stays the default.

### Fixed
- **Splitting no longer leaves a dead table of contents.** A contents list left in one part
  pointed at headings that had moved to other parts. `--split` now points those links at the part
  that holds each heading; `node .keel/doc-size.mjs --relink <doc>` repairs documents split
  before.

Run `/keel upgrade` to adopt these. Each change is offered on its own and applied only with your
approval; a cut from AGENTS.md or CLAUDE.md is offered only after the upgrade shows that its home
already holds the text. Existing decision records and evidence files are never rewritten.

## [2.5.6] — 2026-11-16
<!-- headline: Four fixes to splitting and closeout. -->

Four fixes from real projects: the split tool stays inside your project, references to numbered
sections follow a split, and closeout phases are numbered and counted correctly.

### Fixed
- **Split stays inside the project.** `node .keel/doc-size.mjs --split` follows a part's
  "Part of" link to its parent. It now refuses a link that points outside the project, or to a
  parent whose folder the part is not in, and writes nothing. Security fix.
- **Numbered-section references follow a split.** Plain references such as
  `docs/ARCHITECTURE.md §9.2` (also backticked, bare `ARCHITECTURE.md §9`, or file-relative) are
  repointed to the part that now holds that section, or its nearest numbered parent section.
  Decision records are still never rewritten.
- **Closeout numbering.** A closeout phase is `N.5`, or the next free `N.x` when `N.5` exists
  (`N.15` → `N.16`); no phase is renumbered. `node .keel/doc-size.mjs --closeout
  docs/IMPLEMENTATION_PLAN.md` prints the number and the open deferred rows, split plans included.
  A closeout scope branch may start from a branch that carries an unmerged `/keel upgrade`.
- **Placeholder row not counted.** The italic `*(none yet …)*` row in the Deferred items table is
  no longer counted as open work, and new plans give it status `—` instead of ⬜.

Run `/keel upgrade` to pick these up: it reinstalls `.keel/doc-size.mjs` first. No document
changes are needed; an old placeholder row with ⬜ is offered a one-cell fix.

### Added
- **Parked note: hosted answer link** (`docs/discussions/hosted-answer-link.md`): why a web link
  for team answers is parked, what would unpark it, and its constraints.

## [2.5.5] — 2026-11-16
<!-- audience: internal -->

How Keel treats documentation is now written down, and the docs site has a roadmap page. Nothing
that `/keel` generates changes in this release; the rules below govern every release after it.

### Changed
- **The full documentation set stays.** Keel keeps generating every document that fits a project:
  BRD, PRD, engineering design, architecture, HLD, LLD, ADRs, NFR, design, compliance, threat
  model, plan, runbook and the rest. No document type is removed without the maintainer's typed
  approval. Why: a full documentation set per project is Keel's original requirement, and shorter
  output must not trade it away.
- **Two tiers of document.** *Execution tier* (AGENTS.md, CLAUDE.md, COMMANDS, IMPLEMENTATION_PLAN,
  RUNBOOK, DEPLOYMENT, PRODUCT, the docs and ADR indexes): what agents load and act from. Later
  releases shorten these to facts, pointers and steps, and move "never" rules into hooks and
  settings that enforce them. *Record tier* (BRD, PRD, ENGINEERING_DESIGN, ARCHITECTURE, HLD, LLD,
  ADR files, NFR, DESIGN, COMPLIANCE, THREAT_MODEL, CONNECTOR_SPEC, COST_ANALYSIS, SPIKE, AUDIT,
  FEEDBACK_ROUNDS, CHANGELOG, almanac): kept full and only checked for drift against the code. An
  oversize record doc may still be split or archived word for word, never cut. Why: execution
  files are read on every run, so each extra line costs on every run; record documents are opened
  for one question, and their value is being complete. Nothing leaves an execution file except to
  a record document or an enforced rule.
- **Measure before cutting.** Size budgets and leaner output apply to the execution tier only, and
  only after an evaluation (the same tasks run with no docs, a minimal AGENTS.md and the full Keel
  set) gives a baseline. Its result may recommend shorter execution documents, never a shorter
  record document or a missing document type. Why: the evidence that long context files can lower
  agent success is about always-loaded instructions, and Keel's own effect is not yet measured.

### Added
- **Roadmap page** on the docs site (`docs/site/19-roadmap.md`, `/docs/roadmap/`): Now, Next and
  Later with no dates; the two document tiers; team answers (opt-in packet files); how existing
  projects adopt each change through `/keel upgrade`; and what Keel will not build.

## [2.5.4] — 2026-10-31
<!-- headline: Document size checks got clearer. -->

The doc-size checker no longer overrides an explicit ADR index budget silently.

### Fixed
- **ADR index budget explained.** The budget for `docs/adr/README.md` is the larger of its
  `.keel/meta.json` `budgets` entry and 320 B per ADR, since the index must list every ADR. When
  the ADR count wins, the verdict reason now says so: `ADR index, budget 320 B × 129 ADRs
  (overrides budgets["docs/adr/README.md"] = 16384 B, which is only a floor)`. Found on cortextOS
  (16384 listed, 41280 used). The 16 KB default is documented as a floor; self-test fixture added.

## [2.4.3] — 2026-10-31

Closes the remaining items of the cortextOS 2.4.1 upgrade report (12 issues; 1–4 were fixed in 2.4.2).

### Fixed
- **Redirect stubs and the ADR directory are never split parents** (`# ADR.md → moved`, even with a
  `## Parts` heading), on top of 2.4.2's `## Parts` rule. (issue 1)
- **Nested split docs are checked**: any `docs/**.md` with a `## Parts` heading and a sibling folder
  (`docs/adr/README.md` → `docs/adr/readme/`); nested docs are measured, each file once. (2, 9)
- **`--split` recurses in one run** — cutting at `##` down to `######` — until every new part and
  the cut part's remainder fit. (6)
- **Section order kept**: a cut part's pieces become sub-parts named after it (`02` → `02a`, `02b`),
  listed right after it in the Parts table. (6)
- **A single table over budget splits by rows** (header repeated, new rows go to the last part). (5)
- **ADR files are never rewritten**: link repointing skips them; the index lists moved anchors under
  "Moved sections". The rule is stated in conventions, doc-sync and every mode. (7)
- **Backticked `` `docs/NAME.md#anchor` `` pointers are repointed** like markdown links. (8)
- **Writers are split-aware**: `--where <doc> "<section>"` prints the file holding a section;
  change-template, phase-template, doc-sync and the phase / change / closeout / archive / upgrade
  modes write there, never into an index. (10)
- **Keystone headroom**: `--move-out AGENTS.md "<section>"` moves a whole section to
  `docs/agents/NN-<slug>.md` (linked both ways). Upgrade checks headroom before adding keystone
  text and proposes a move-out, never compression. (11)
- **`/keel upgrade` installs `.keel/doc-size.mjs` first, from any version.** (12)

### Tested
- Self-test fixtures for each issue. On a scratch clone of cortextOS `2c5e5a8`: exit 0, 27 files
  each measured once, 0 link errors. Four docs split in one pass each with nothing left over budget
  and `docs/adr/` untouched. With the plan's waiver removed, the plan splits too: the 71 KB deferred
  table is cut by rows, and `--where` finds the right part.

## [2.4.2] — 2026-10-31

Fixes the conflicts a real `/keel upgrade` to 2.4.1 hit on a large project (cortextOS), generically.

### Changed
- **`doc-size.mjs` gives one verdict per doc** — `ok` / `waived` / `archive` / `split` / `manual`,
  each with its reason. doc-sync acts on `archive` and `split` only; `manual` is reported.
- **Archives are never budgeted or split** (`*ARCHIVE*`, `LEGACY_*`, `archive/`, meta `"archives"`);
  `--split` refuses them.
- **A folder beside a doc is a split only if the doc has a `## Parts` heading** — `docs/ADR.md`
  next to `docs/adr/` no longer produced 260 false link errors or measured ADR files as parts.
- **ADR index budget scales with the ADR count** (320 B per `ADR-*.md`); over that → `manual`.
- **Keystone over budget**: archive, then move whole sections out to `docs/agents/NN-<slug>.md`
  behind a `## Parts` table (checked both ways) — never compress wording. "tight" note under 2% headroom.
- **Archive-then-split** is now two verdicts: `archive`, then `split` only on the re-check after
  archiving (`--after-archive`).
- **Generated files and docs without headings** → `manual` instead of a split that fails or is overwritten.
- **Link check** reads reference-style links, angle-bracket links and repo-absolute `/docs/x.md`.
- **`--split` is idempotent**: on an index with nothing new it refuses and changes nothing; new
  sections written into an index move out and append rows to the existing Parts table.

### Added
- **Waivers** in `.keel/meta.json` — `"waivers": {"<doc>": {"reason", "reviewed", "max"?}}`,
  "review due" after `waiverReviewDays` (90). Only the user grants one. Legacy `budgetExceptions`
  are read as unreviewed waivers; `/keel upgrade` moves them after asking.
- Self-test fixtures for every case above (archive, ADR folder + index, legacy and current waivers,
  waiver `max`, generated, no headings, reference/absolute links, tight and over-budget keystone,
  keystone parts, repeat split, new section in an index).

## [2.4.1] — 2026-10-31

### Added
- **`node .keel/doc-size.mjs --split <doc>`** — deterministic split per the 2.4.0 rule: a plain
  doc's `## ` sections move verbatim to `docs/<name>/NN-<slug>.md` (small neighbours merged,
  headings inside code fences ignored) and the parent becomes an index with a Parts table; an
  oversize part keeps its first chunk and moves the rest to new parts added to the index; inbound
  `NAME.md#anchor` links are repointed. Refuses the keystone. The self-test appends to an
  over-limit doc and asserts the split, the links both ways, the repointed link, a second split
  of a grown part, and a clean check afterwards.

### Changed
- **Split-aware doc sync.** `SYNC_RULES` and `.claude/agents/doc-sync.md` now require: write into
  the right part of a split doc, never the index; a part about to breach gets a new part (linked
  both ways) or `--split`; a plain doc an edit would push over budget is split, not piled on. The
  caller's review round checks index-stays-index, links both ways and no breach. The size/link
  check is the last step before the doc-sync commit (no commit with a link error). The Split
  stage runs `--split` first. Security/design subagents follow the same rules if they edit a doc.
- Docs site: split layout covered on Roles, Version (Budgets row), Archive (tool + writing to a
  split doc), "Where things live" and the catalog; badge 2.4.1.

## [2.4.0] — 2026-10-31

### Added
- **Auto-split oversize docs.** A doc over its budget is no longer just reported. Archivable docs
  (IMPLEMENTATION_PLAN, CHANGELOG, RUNBOOK, DEPLOYMENT, ADR index) relocate closed detail first;
  anything still over is split into a sibling folder (`docs/DESIGN.md` → `docs/design/NN-<slug>.md`,
  one part per top-level section, content verbatim, IDs unchanged). The parent becomes a slim index
  whose Parts table links every part; each part links back; inbound anchor links are repointed.
  The keystone (AGENTS.md, CLAUDE.md) is never split — archive only, else `BUDGET_EXCEEDED`.
- **`keel-doc-size.mjs`** (`.keel/doc-size.mjs` in projects): measures every doc once — a split
  doc's index and each part separately against the parent's budget, family total reported, no

## [2.0.0] — 2026-09-20

Shaped by a retrospective across four keel-documented production projects (mysha, interview-strategist,
ospraye, cortextOS — ~1,800 commits, ~600 doc-touching). The pattern in every one: docs stayed
trustworthy only when every claim carried evidence, and stayed readable only when the journal lived
somewhere other than the keystone. **Breaking:** doc format 2 — existing projects migrate via
`/keel upgrade` (FORMAT_MIGRATION).

### Added
- **Evidence ladder** (`code-read < unit < integration < local-browser < staging < prod-live`). Every
  ✅ carries a level + artefact. Exit gates are tables (`Gate · Evidence level · Artefact · Verified
  by · Status`); a gate whose evidence falls short of its wording is `partial` and the phase stays
  open. Standing rule 7: *claims carry evidence*.
- **Deploy-state ladder** (`on-branch → merged → deployed vNN → live-verified`) with one home:
  `CHANGELOG.md` + `DEPLOYMENT.md` deploy log. Flipped by the Merge step and the deploy procedure,
  never by prose — kills the "flip pre-merge language" commits.
- **Verify stage** in `phase-template.js` between Integrate and Doc Sync: runs every suite once,
  records skipped tests by name, and writes `.keel/evidence/phase-N.json`; doc-sync cites it and
  never re-runs. `prod-live` cannot be written by scripts, only by a deploy.
- **ADR reservation at scope**: the phase script's Setup reserves `ADR-NNN` stubs so parallel
  worktrees never collide on numbers; migrations are timestamp-named.
- **Two work units**: `/keel phase new <slug> [--after N | --split N]` (gated milestone, fractional
  numbering rules) and `/keel change <slug>` (hotfix-weight: `chg/` branch, `CHG-xxx` row,
  CHANGELOG line, `change-template.js`, no phase block). `/keel closeout` generates a deferred-items
  sweep phase past a threshold.
- **Byte budgets + auto-archive**: `.keel/meta.json` `budgets` (keystone 12 KB default); doc-sync's
  deterministic Budget step measures every living doc and runs the archive per breached file, one
  commit each; reports `BUDGET_EXCEEDED` and stops rather than loop.
- **New templates**: `DEPLOYMENT.md` (env matrix, promotion path, build-time vs runtime config,
  pre/post-deploy checklists, rollback, deploy log, gotchas — one doc for all environments),
  `CHANGELOG.md`, `SPIKE.md`, `COST_ANALYSIS.md`, `AUDIT.md`, `FEEDBACK_ROUNDS.md`,
  `keel-meta.json`; `docs/keel-transcript.md` is now a standard output.
- **Decider tags** (`founder` / `engineering` / `legal`) on ADRs and open decisions; open decisions
  are one row per *question* with a Locations column.
- `/keel version` reports doc format and per-file size vs budget.

### Changed
- **ADRs are per-file and table-based** (`docs/adr/ADR-NNN-slug.md`, index + open decisions in
  `docs/adr/README.md`): header table, ≤2-sentence context, Y-statement decision, options with ✓/✗,
  consequences incl. a single `Build deviation` row. Lifecycle `Proposed → Accepted → Built →
  Superseded`. **Addenda abolished** — incidents go to RUNBOOK postmortems, deploy status to the
  deploy log.
- **AGENTS.md is the canonical keystone**; `CLAUDE.md` is `@AGENTS.md` + Claude-only sections.
  Status is a two-row table; hard invariants are `Rule · Enforced by · Gap · Source`; a pre-PR
  checklist is derived from them.
- `RUNBOOK.md`: environments/deploy/rollback moved to DEPLOYMENT; playbooks are `Symptom · Check ·
  Fix · Escalate` tables; new Postmortems register (`PM-xxx`).
- `COMMANDS.md`: deployment section is commands-only; new seed/test-data and local↔remote data
  reconciliation sections; env-var table gains a build-time/runtime `Kind` column.
- `ENGINEERING_DESIGN.md` non-negotiables gain `Enforced by · Exception path · Gap` columns.
- Deferred items gain `Owner · Revisit trigger`; phase-status table gains `Deploy state`.
- `/keel upgrade`: format-1 detection, `FORMAT_MIGRATION` + `BUDGET_EXCEEDED` gap classes, and the
  U0–U7 migration sequence (archive first; classify addenda/status prose with verbatim relocation;

- `/keel archive`: categories renamed/added — `KEYSTONE_DRIFT`, `CHANGE_MERGED`,
  `CHANGELOG_OVERFLOW`, `POSTMORTEM_CLOSED`; DEPLOYMENT env matrix and evidence files are never
  archived.
- Delivery/Ops interview round asks about environments, promotion path, build-vs-runtime config,
  deploy authority, and live-verification checks.
